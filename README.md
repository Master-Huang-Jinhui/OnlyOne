# Only One BBQ & Tea 一站式管理系统

> 轻量级全栈点餐 + 外卖平台管理系统，基于 Node.js + SQLite + React，支持 Mac/Win 双平台、局域网访问、数据可复制迁移。

## 功能总览

系统包含 **四个端**：前台顾客端、后台管理端、员工点餐端、外卖平台跳转管理。

### 🏠 前台顾客端（无需登录）
- **首页**：全宽轮播图、新品上市、品牌故事、茶品溯源（动态可配置）、奶茶工艺互动制作器、自定义内容板块、商品菜单、联系我们、页脚
- **商品菜单**：分类筛选、商品展示、口味选择（单选/多选/自定义备注）、一键加购、商品角标显示已点数量
- **购物车**：连续加购不跳转、数量调整、备注编辑（仅购物车内）、同商品不同备注自动分开、口味标签展示、历史订单记录
- **结算**：自取/配送两种方式（自取填姓名电话，配送填地址电话姓名）、税率自动计算（默认 8.875%）、配送费规则（满额免配送）、营业状态校验（休息时拦截下单）
- **订单查询**：顾客凭订单号/手机号/姓名查询自己的订单，设备隔离（只能看自己的）
- **堂吃扫码**：餐桌二维码扫码直接进入菜单，同桌多次点餐合并结算
- **响应式设计**：适配手机/平板/电脑，滚动动画、悬浮侧边导航、淡入淡出效果

### 🛠️ 后台管理端（需登录，admin/manager 角色）
- **仪表盘**：今日订单/营收统计、待处理订单（分页、可点击跳转）、热销商品 TOP5、备忘录/重点事项（优先级排序）
- **外卖平台管理**：Logo 上传、名称、中转跳转 URL（不暴露真实地址）、账号密码（仅 admin 可见）、电话、备注、启用状态、每周上下架/缺货记录
- **商品管理**：商品增删改查、分类管理（一级大类）、推荐标记、上下架、图片上传、批量移动分类、模糊搜索、分页、Excel 批量导入导出（含模板下载）
- **口味管理**：大类（辣度/冰度/甜度/配料/其他）+ 小类（少冰/去冰/微辣等），可单独开关、设置额外加价（如去冰 +$1）、默认选中、绑定适用商品分类（奶茶才有冰度，烧烤才有辣度）
- **订单管理**：订单列表（默认今日、可按时间范围查询精确到小时）、状态筛选、订单详情、状态推进（后台可配置流转）、分页、按订单号/金额/时间排序、模糊搜索
- **订单状态管理**：动态配置订单状态（按用餐方式区分：堂吃/打包/配送）、状态名称、颜色、是否进行中、下一状态、推进按钮文字、可开关
- **餐桌管理**：餐桌增删改查、桌号、状态（空闲/占用）、清桌（合并订单结算后生成新会话）、扫码二维码生成
- **用户管理**：用户增删改查、四种角色（admin 超级管理员 / manager 管理员 / employee 员工 / user 普通用户）、启用禁用、修改密码
- **权限管理**：基于菜单的角色权限分配，可指定用户能看哪些菜单和内容
- **菜单管理**：一级/二级菜单动态配置（最多二级）、图标、路径、排序、启用禁用、表单可绑定到二级菜单
- **表单管理**：自定义表单构建器，支持文本/数字/下拉/单选/多选/日期/时间/开关/文本域等字段，提交记录查看，可绑定到菜单
- **内容管理**：轮播图管理、品牌故事/茶品溯源/奶茶工艺/关于区块（中英双语）、茶品动态添加删除+图标上传+单独启用开关、自定义内容板块（图片左右布局、鼠标特效）、新品上市（图片+名称+描述，无新品时显示提示语）
- **货物管理**：货物（原材料）库存管理、进货单管理、进货明细、自动更新库存和均价、模糊搜索、按供应商/日期筛选
- **销售统计**：菜品销量排行、热销/平销/滞销分类、TOP5 热销、利润计算器（采购价/磅数/售价/出份数自动计算利润率、回本次数）、Excel 导入导出、历史记录自动填充
- **系统设置**：店铺信息、营业时间（7 天独立配置，周二默认休息）、税率、配送规则、多语言配置、堂吃二维码生成（支持自定义局域网地址）

### 👨‍🍳 员工点餐端（需登录，employee 角色）
- **欢迎主页**：大欢迎界面、打卡按钮（上下班多次打卡，取最早/最晚时间）、堂吃/打包两个点餐入口、左上角 Logo + OnlyOne 标识、右上角修改密码/退出登录
- **堂吃点餐**：选择桌子 → 点餐（同桌未结算订单直接显示，可加单）→ 下单送后厨 → 多次点餐合并到同一桌 → 结算清桌
- **打包点餐**：直接点餐 → 下单生成取餐号 → 待取餐 → 确认取餐
- **购物车**：与前台一致，口味选择、备注编辑、商品角标
- **订单管理**：今日订单列表、订单详情、状态推进（制作中→待取餐→已完成）、订单查询

### 🛵 外卖平台跳转管理
- 后台配置各平台（Uber Eats、DoorDash、Grubhub、Google、HungerPanda、小灰云、Yelp、BeyondMenu 等）
- 前台/后台点击平台卡片通过**中转路由** `/go?platform=id` 跳转，不暴露真实 URL
- 支持 Logo、账号密码、电话、备注、每周上下架状态

## 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端 | Node.js + Express | 轻量 Web 服务，监听 0.0.0.0:3000 |
| 数据库 | SQLite + better-sqlite3 | 单文件数据库（`backend/data.db`），复制即用，WAL 模式 |
| 前端 | React 18 + Vite | 组件化开发，快速构建 |
| 样式 | Tailwind CSS | 原子化 CSS，浅蓝色 + 白色主题 |
| UI 组件 | 自研 shadcn 风格组件 | Toast（屏幕正上方）、Modal、Button、Input 等 |
| 认证 | JWT + bcryptjs | 无状态登录（7 天有效期），密码 bcrypt 哈希 |
| 文件上传 | multer | 图片上传到 `backend/uploads/images/`，Excel 上传到 `backend/uploads/profit/` |
| Excel 处理 | xlsx (SheetJS) | 商品/利润数据批量导入导出 |
| 动画 | CSS + IntersectionObserver | 滚动淡入上移、奶茶制作器动画、视差滚动 |

## 快速开始

### 环境要求
- **Node.js 22 LTS**（⚠️ Node 24 不兼容 better-sqlite3，必须使用 22 或更低 LTS 版本）
- Windows 10/11 或 macOS 10.15+
- 现代浏览器（Chrome / Edge / Safari）

### 安装与运行

#### 方式一：启动脚本（推荐）

**Windows**：双击 `启动.bat`

**Mac**：
```bash
chmod +x 启动.command
./启动.command
```
或直接双击 `启动.command`（如遇权限问题先执行上面的 chmod 命令）

首次运行会自动安装依赖并构建前端，需要几分钟。启动后自动打开浏览器访问 `http://localhost:3000`

#### 方式二：手动命令行

```bash
# 1. 安装后端依赖
cd backend
npm install

# 2. 安装前端依赖并构建
cd ../frontend
npm install
npm run build

# 3. 启动后端服务（同时服务前端 dist 静态文件）
cd ../backend
node src/server.js
```

浏览器访问 `http://localhost:3000`

### 默认账号

| 角色 | 账号 | 密码 | 说明 |
|------|------|------|------|
| 超级管理员 | `admin` | `admin` | 全部权限，可查看平台密码 |
| 管理员 | 后台创建 | 后台设置 | 管理权限，不可查看平台密码 |
| 员工 | 后台创建 | 后台设置 | 仅员工点餐端 |
| 普通用户 | 前台注册/后台创建 | 后台设置 | 仅前台顾客端 |

## 局域网访问

1. 确保所有设备连接同一个 WiFi
2. 启动服务后，控制台会显示本机地址 + 局域网地址（如 `http://192.168.1.100:3000`）
3. 其他设备浏览器输入该地址即可访问
4. **Windows** 需要在防火墙弹窗中允许"专用网络/公用网络"访问
5. 电脑主机必须保持开机，服务不能关闭
6. **堂吃二维码**：后台 → 系统设置 → 堂吃二维码，支持自定义局域网地址生成，打印贴餐桌，顾客扫码直接访问菜单

## API 接口规范

所有业务接口统一使用 **POST** 方法，路径按操作类型区分：

| 操作 | 路径规则 | 示例 |
|------|----------|------|
| 列表 | `POST /list` | `POST /api/products/list` |
| 详情 | `POST /detail/:id` | `POST /api/orders/detail/123` |
| 新增 | `POST /` | `POST /api/products` |
| 更新 | `POST /update/:id` | `POST /api/products/update/1` |
| 删除 | `POST /delete/:id` | `POST /api/products/delete/1` |

特殊保留 GET 的路由（浏览器地址栏/二维码访问）：
- `/table?s=桌号` — 堂吃扫码入口
- `/go?platform=id` — 外卖平台中转跳转
- `/go?carousel=id` — 轮播图中转跳转
- `/api/health` — 健康检查

查询参数通过 URL query 传递（如 `/api/orders/list?status=pending&page=1`），后端用 `req.query` 读取。

所有 SQL 查询使用**参数化查询**，无 SQL 注入风险。

## 数据迁移与备份

### 迁移到另一台电脑
整个 `OnlyOne` 文件夹复制到 U 盘 / 云盘 / 另一台电脑，双击启动脚本即可运行。所有数据都在 `backend/data.db` 中。

> ⚠️ 多台电脑的数据独立，不会自动同步，需要手动复制文件夹覆盖。

### 每日备份建议
1. 关闭后端服务（确保数据写入完成）
2. 复制 `backend/data.db` 到备份目录（可加日期后缀，如 `data_20260909.db`）
3. 也可推送到 GitHub 私有仓库做版本管理

## 常见问题

### Q: 启动报错 `better-sqlite3` 编译失败
A: 确认 Node.js 版本为 **22 LTS**。Node 24 没有 better-sqlite3 预编译二进制且 Windows 缺编译环境。使用 `nvm` 或官网下载 Node 22。

### Q: 前端页面空白或 API 404
A: 前端修改后必须重新 `npm run build`，然后重启后端。浏览器强制刷新（Mac: `Cmd+Shift+R`，Win: `Ctrl+Shift+R`）清除缓存。

### Q: 订单号每天会重置吗？
A: 会。订单号格式 `MMDD-NNN`，每天从 001 开始，跨天不重复。内部 `id` 始终自增不重复。

### Q: 堂吃同一桌多次点餐怎么结算？
A: 同一桌在未清桌前，所有订单绑定同一个 `table_session`。点餐时直接显示该桌已有订单，可继续加单。清桌时自动合并所有订单为一个，状态设为已完成，然后生成新会话。

### Q: 数据怎么备份？
A: 关闭后端服务后，复制 `backend/data.db` 到备份位置即可。也可以整个项目文件夹推送到 GitHub 私有仓库。

### Q: SQLite 支持多少并发？
A: 单店场景（每天几百单）完全够用。SQLite 支持 WAL 模式下的并发读，写操作串行。如果未来需要多店高并发，可迁移到 MySQL/PostgreSQL。

### Q: 口味怎么绑定到特定商品分类？
A: 后台 → 口味管理 → 编辑大类 → 设置"适用商品分类"。比如"冰度"大类只绑定"招牌奶茶"和"鲜果茶"分类，烧烤类商品就不会显示冰度选项。不选表示全部适用。
